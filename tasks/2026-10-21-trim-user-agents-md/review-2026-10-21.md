## Findings

### 1. P2 — The shared skill incorrectly rules out `/print` in every build

**Introduced in `agent-house` commit `1a42146`.**

The skill states: “A built deck has no `/print` route.” See [SKILL.md](/Users/martin/Develop/agent-house/user/skills/slidev/SKILL.md:66).

That depends on build configuration. Installed Slidev 53.0.0 enables print routes during a build when `download` is `true`, `"true"`, or `"auto"`. See [the CLI feature definition](/Users/martin/Develop/slidev/stem/work1/watches/node_modules/@slidev/cli/dist/serve-DzvJFv6v.mjs:1126). The client then registers `/print` in [routes.ts](/Users/martin/Develop/slidev/stem/work1/watches/node_modules/@slidev/client/setup/routes.ts:61).

The current Watches headmatter does not enable `download`. The warning can describe that deck’s configuration, but it is incorrect as a general Slidev rule.

**Impact:** An agent can reject a supported print workflow or diagnose its absence incorrectly.

**Alternatives:**

- **Preferred:** State the configuration condition. Keep `/N?print=clicks` as the single-slide inspection path.
- Describe only the current Watches configuration in its project docs.
- Remove the route claim. This avoids the error but loses useful guidance.

### 2. P2 — Scope persistent visuals to continuity requirements

**An existing house rule becomes broader through the shared-skill migration.**

The skill requires every visual used on multiple slides to be one persistent element. See [SKILL.md](/Users/martin/Develop/agent-house/user/skills/slidev/SKILL.md:84).

That is useful when one animated subject must move continuously between slides. It is unnecessary for a repeated logo, a static diagram, or independent instances of one component.

Installed Slidev source confirms the lifecycle issue: slides preload and remain mounted. See [SlidesShow.vue](/Users/martin/Develop/slidev/stem/work1/watches/node_modules/@slidev/client/internals/SlidesShow.vue:32). That explains the continuity requirement; it does not require all repeated visuals to become global.

The neighbouring direction rule also loses a useful boundary. The old navigation document ended its direction warning with “the layer decides that.” The shared version gives an unqualified prohibition. See [SKILL.md](/Users/martin/Develop/agent-house/user/skills/slidev/SKILL.md:79).

**Impact:** A simple deck can acquire global state, slide lookup logic, and export handling without a teaching or animation need.

**Alternatives:**

- **Preferred:** Require a persistent element when visual continuity across slides is required. Let the animation layer determine transition behaviour.
- Keep stronger animation defaults in project docs, and label them as project policy.
- Keep the universal rule. This is simplest to state, but imposes unnecessary implementation work.

### 3. P3 — Describe tool restrictions separately from action restrictions

**The enforcement wording is introduced in `agent-house` commit `1a42146`.**

The harness document says OpenCode permissions “enforce the limits.” See [harnesses.md](/Users/martin/Develop/agent-house/docs/harnesses.md:81).

The converter denies editing tools separately from shell access. The reviewer permits `Bash`, and the tests explicitly preserve it when editing is denied. See [convert-agent.py](/Users/martin/Develop/agent-house/tools/convert-agent.py:35), [the reviewer configuration](/Users/martin/Develop/agent-house/user/agents/review-quality-slidev.md:4), and [test-install](/Users/martin/Develop/agent-house/tools/test-install:353).

Shell commands can write files or make network requests. Thus, these permissions restrict named tools. They do not establish a complete read-only or no-network boundary.

**Impact:** Maintainers can overestimate what the converted permissions guarantee. No prohibited action was observed in this review.

**Alternatives:**

- **Preferred:** Explain the tool-level boundary. Retain the reviewer’s explicit prohibition on writes.
- Use a session-level filesystem or network boundary when hard enforcement is required.
- Deny shell access. This removes useful source inspection and validation capabilities, so it is a poor default.
