## Findings

### 1. P2 — The task preservation rule contradicts required updates

The new text says that nothing in a task directory is updated later. See [user/AGENTS.md](/Users/martin/Develop/agent-house-trim/user/AGENTS.md:36).

The same section requires a dated change to a task’s README when a later decision supersedes it. See [line 68](/Users/martin/Develop/agent-house-trim/user/AGENTS.md:68).

The original preservation requirement attached to copied inputs. See [the preserved input](/Users/martin/Develop/agent-house-trim/tasks/2026-10-21-trim-user-agents-md/inputs/user-AGENTS.md:29). The rewrite extends it to the whole directory.

The new Work1 task amendment demonstrates why the exception is needed.

**Impact:** An agent cannot obey both rules when it must update an existing task README.

**Alternatives:**

1. **Preferred:** Keep preserved inputs unchanged. Explicitly permit dated README updates.
2. Permit appended updates throughout the task directory. Define the boundary between evidence and commentary.
3. Remove dated updates. This keeps tasks fixed but loses the warning that a decision has changed.

### 2. P3 — Separate measured text reduction from token estimates

The new instruction says table padding can double a file’s tokens. See [user/AGENTS.md](/Users/martin/Develop/agent-house-trim/user/AGENTS.md:44).

The task estimates tokens at four characters per token. See [PLAN.md](/Users/martin/Develop/agent-house-trim/tasks/2026-10-21-trim-user-agents-md/PLAN.md:8). No tokenizer measurement is preserved.

Token counts depend on the tokenizer. A character reduction does not establish the same percentage reduction in tokens, particularly for repeated spaces.

**Impact:** The preference for lists is reasonable, but its quantitative justification is stronger than the evidence.

**Alternatives:**

1. **Preferred:** Justify lists through wrapping and reduced padding. Report measured character or byte counts.
2. Measure representative files with a named tokenizer, and label the results as tokenizer-specific.
3. Keep the four-character estimate as a rough planning estimate, without using it to support the doubling claim.

A minor correction: the preserved input contains 10,910 Unicode characters and 10,912 UTF-8 bytes. The plan calls the latter characters.

### 3. P3 — Preserve enough scan evidence to support the skill-loading conclusion

The plan reports two Skill calls and ten reads of the Slidev skill. It then draws a general conclusion about reliable loading. See [PLAN.md](/Users/martin/Develop/agent-house-trim/tasks/2026-10-21-trim-user-agents-md/PLAN.md:14).

The preserved scanner:

- Selects the current latest 50 transcripts by modification time.
- Counts tool names and Skill inputs.
- Does not count the filenames opened by Read calls.

See [sample selection](/Users/martin/Develop/agent-house-trim/tasks/2026-10-21-trim-user-agents-md/inputs/scan.py:12) and [tool counting](/Users/martin/Develop/agent-house-trim/tasks/2026-10-21-trim-user-agents-md/inputs/scan.py:38).

This script cannot reproduce the stated ten Slidev-skill reads. A later run will also select a different sample.

**Impact:** The explicit triggers are sensible, but a future reader cannot reconstruct all the evidence behind the decision.

**Alternatives:**

1. **Preferred:** Preserve sanitized aggregate output and sample-selection details. Identify manual counts and qualify the reliability statement as an inference.
2. Extend the preserved scanner to count relevant Read paths, and save its aggregate results.
3. Retain the evidence but soften the conclusion to an observation from this sample.

Raw transcripts need not enter this public repository.

### 4. P3 — Consider a general fallback for quality reviews

The new skill asks the user when no specialist reviewer fits. The repository supplies only `review-quality-slidev`. See [SKILL.md](/Users/martin/Develop/agent-house-trim/user/skills/quality-review/SKILL.md:8) and [the reviewer’s scope](/Users/martin/Develop/agent-house-trim/user/agents/review-quality-slidev.md:3).

This is an explicit policy choice. The specialist coverage gap also predates this change. However, the generic skill is a useful place to resolve it.

**Impact:** Reviews of Python tools or agent configuration can require clarification despite having enough source and review criteria.

**Alternatives:**

1. **Preferred:** Permit a general reviewer, or a local review using the same reporting contract, when no specialist fits.
2. Add a general `review-quality` subagent. This adds another maintained prompt.
3. Keep the mandatory question. This preserves strict specialist selection but adds an interruption.
